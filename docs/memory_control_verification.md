## 全链路实测

测试文字：`记住：我喜欢喝无糖拿铁。`

1. 立即返回 `queued`，提供带 `persisted: false` 的待保存原文。
2. 不继续发用户消息，实际等待 agent 连续空闲 120 秒。
3. 后台 Graphiti 抽取、写入完成，状态变为 `applied`。从提交到完成约 **124.74 秒**，包括 120 秒等待。
4. 询问饮料偏好，返回 4 条长期检索材料，包含拿铁。
5. 发送 `忘记：拿铁`，返回候选及关联来源范围；确认后返回 `applied`。
6. 再次询问饮料偏好，长期召回为 0 条。
7. 重启服务后，保存和删除操作的既有回执仍可读取。

这是一条小规模功能验证，不代表已经完成大规模准确率、并发或安全审计。

## 改动位置

- `control_store.py`：持久化操作、请求幂等签名、审计、来源撤回、agent 活动时间和独立空闲快照。
- `memory_control.py`：规则解析、操作编排、选择确认、回执核对和 v2 作用域过滤。
- `control_graph.py`：Neo4j 来源账本、事实版本检查、原子删除回执、旧来源屏蔽及新来源重新确认。
- `control_api.py` / `control.html`：独立控制密钥、v2 API 和文字测试页。
- 现有 worker、consolidator、session/turn store、engine：接入空闲整理和抽取前来源过滤，保留旧 v1 返回格式。
- SQLite schema 升至 10，旧版本程序会拒绝直接读取新库，避免降级后忽略快照领取状态而重复抽取。

接入方法及限制见 [文字记忆控制说明](memory_control.md)。
